Linux에서 대부분의 자원은 파일 형태로 표현된다. 이 글에서는 파일시스템 계층 구조, 파일 관리 명령어, 링크, Shell 확장, 권한과 `umask`를 정리한다.

## 1. 파일시스템이란?

파일시스템은 저장장치의 데이터를 파일과 디렉터리 형태로 저장하고 찾기 위한 규칙과 구조다. 디스크에 파티션만 만든 상태에서는 일반 파일을 저장할 수 없으며, XFS나 ext4 같은 파일시스템을 생성한 뒤 디렉터리에 마운트해야 사용할 수 있다.

RHEL은 일반 데이터 영역에 XFS를 기본 파일시스템으로 널리 사용한다. ext4도 지원하며 용도와 운영 정책에 따라 선택한다.

## 2. Linux 파일시스템 계층 구조

Linux는 드라이브 문자 대신 `/`를 최상위로 하는 하나의 디렉터리 트리를 사용한다. 다른 디스크나 네트워크 파일시스템도 특정 디렉터리에 마운트해 이 트리에 연결한다.

| 위치 | 역할 | 예시 |
|---|---|---|
| `/boot` | 부팅에 필요한 Kernel, initramfs, GRUB 파일 | `/boot/grub2` |
| `/dev` | 장치를 나타내는 특수 파일 | `/dev/sda`, `/dev/nvme0n1` |
| `/etc` | 시스템과 서비스 설정 | `/etc/fstab`, `/etc/ssh/sshd_config` |
| `/home` | 일반 사용자의 홈 디렉터리 | `/home/user01` |
| `/root` | root 사용자의 홈 디렉터리 | `/root` |
| `/run` | 현재 부팅 동안 유지되는 PID·소켓 등 | `/run/sshd.pid` |
| `/tmp` | 임시 파일 | 정리 주기는 시스템 정책에 따라 다름 |
| `/usr` | 프로그램, 라이브러리, 공유 데이터 | `/usr/bin`, `/usr/lib` |
| `/var` | 로그·캐시·스풀처럼 계속 변하는 데이터 | `/var/log` |
| `/proc` | Kernel과 프로세스 정보를 제공하는 가상 파일시스템 | `/proc/meminfo` |

## 3. 절대 경로와 상대 경로

- **절대 경로**는 `/`부터 시작하는 정확한 위치다. 현재 위치와 관계없이 같은 대상을 가리킨다.
- **상대 경로**는 현재 작업 디렉터리를 기준으로 한다.

```bash
pwd
cd /var/log
cd ../tmp
cd ~
```

`.`은 현재 디렉터리, `..`은 상위 디렉터리, `~`는 현재 사용자의 홈 디렉터리를 뜻한다.

## 4. 파일 관리 명령어

```bash
ls -al /etc
mkdir -p /tmp/lab/data
touch /tmp/lab/data/test.txt
cp -a /tmp/lab /tmp/lab-copy
mv /tmp/lab-copy /tmp/archive
rm -r /tmp/archive
```

- `ls -l`: 파일 유형, 권한, 소유자, 크기, 변경 시간을 표시한다.
- `mkdir -p`: 필요한 상위 디렉터리까지 함께 만든다.
- `cp -a`: 속성과 디렉터리 구조를 가능한 한 보존해 복사한다.
- `mv`: 파일을 이동하거나 이름을 변경한다.
- `rm -r`: 디렉터리와 내부 내용을 재귀적으로 삭제한다. 삭제 전 경로를 반드시 확인한다.

## 5. 하드 링크와 심볼릭 링크

### 하드 링크

하드 링크는 같은 inode, 즉 같은 실제 파일 데이터를 가리키는 또 다른 이름이다.

```bash
ln original.txt hardlink.txt
ls -li original.txt hardlink.txt
```

원본 이름을 삭제해도 다른 하드 링크가 남아 있으면 데이터는 유지된다. 일반적으로 디렉터리에는 만들 수 없고, 서로 다른 파일시스템을 넘을 수 없다.

### 심볼릭 링크

심볼릭 링크는 대상의 경로를 저장하는 별도 파일이다.

```bash
ln -s /var/log/messages messages-link
ls -l messages-link
```

디렉터리나 다른 파일시스템을 가리킬 수 있지만 대상이 이동하거나 삭제되면 끊어진 링크가 된다.

## 6. Globbing

Globbing은 Shell이 와일드카드 패턴과 일치하는 파일 이름을 명령 실행 전에 펼쳐 주는 기능이다.

```bash
ls *.log
ls file?.txt
ls report[0-9].txt
```

- `*`: 문자 0개 이상
- `?`: 임의의 문자 1개
- `[0-9]`: 지정한 범위의 문자 1개

Globbing은 정규표현식과 문법과 처리 주체가 다르다. Globbing은 Shell이 파일 이름을 확장하고, 정규표현식은 `grep` 같은 프로그램이 문자열을 검색할 때 사용한다.

## 7. 기본 권한

`ls -l` 결과의 권한은 파일 유형과 소유자(User), 소유 그룹(Group), 그 외 사용자(Other)의 권한으로 나뉜다.

```text
-rwxr-x--- 1 user01 dev 1200 Sep 28 10:00 run.sh
│└─u─┘└g┘└o┘
파일   권한
유형
```

| 권한 | 숫자 | 일반 파일 | 디렉터리 |
|---|---:|---|---|
| `r` | 4 | 내용 읽기 | 목록 조회 |
| `w` | 2 | 내용 변경 | 내부 항목 생성·삭제 |
| `x` | 1 | 실행 | 디렉터리 진입과 항목 접근 |

```bash
chmod 750 run.sh
chmod u+x run.sh
chown user01:dev run.sh
```

디렉터리의 삭제 권한은 파일 자체보다 부모 디렉터리의 `w`와 `x` 권한에 영향을 받는다는 점이 중요하다.

## 8. 특수 권한

- **SUID(4)**: 실행 파일이 파일 소유자의 유효 권한으로 실행된다. `chmod u+s file`
- **SGID(2)**: 실행 파일은 파일 그룹 권한으로 실행된다. 디렉터리에 설정하면 새 항목이 디렉터리 그룹을 상속한다. `chmod g+s dir`
- **Sticky Bit(1)**: 공용 디렉터리에서 파일 소유자, 디렉터리 소유자, root만 해당 파일을 삭제할 수 있게 한다. `/tmp`가 대표적이다. `chmod +t dir`

```bash
chmod 2770 /shared
chmod 1777 /public
```

## 9. umask

`umask`는 새 파일과 디렉터리에서 제거할 권한을 지정한다. 일반 파일은 실행 권한 없이 최대 `666`, 디렉터리는 최대 `777`에서 시작한다.

```bash
umask
umask 027
```

`umask 027`이면 일반 파일은 보통 `640`, 디렉터리는 `750`으로 생성된다. 기본값이 항상 `022`인 것은 아니며 로그인 방식과 Shell 설정에 따라 달라질 수 있다. 사용자별 영구 설정은 `~/.bashrc`나 `~/.bash_profile`, 시스템 정책은 `/etc/profile` 계열 설정을 확인한다.

파일 권한을 설정할 때는 동작 여부만 보지 말고, 필요한 사용자에게 필요한 만큼만 권한을 부여했는지 확인하는 것이 핵심이다.
