Linux는 사용자와 그룹을 기준으로 파일과 프로세스의 권한을 구분한다. 이 글에서는 계정 정보 파일, 사용자·그룹 관리, `su`와 `sudo`, 암호 만료 정책을 정리한다.

## 1. 사용자와 그룹

운영체제는 사용자 이름보다 숫자인 UID로 사용자를 식별한다. 그룹도 GID로 식별한다.

- **root**: UID 0을 사용하는 최고 관리자 계정이다.
- **시스템 사용자**: 서비스와 데몬을 분리된 권한으로 실행하기 위한 계정이다. 보통 대화형 로그인을 사용하지 않는다.
- **일반 사용자**: 사람이 로그인해 작업하는 계정이다. RHEL의 일반 사용자 UID는 기본적으로 1000부터 시작하지만 `/etc/login.defs` 설정에 따라 달라질 수 있다.

모든 사용자는 하나의 기본 그룹을 가지며, 여러 보조 그룹에 추가될 수 있다.

```bash
id user01
getent passwd user01
getent group dev
```

## 2. 계정 정보 파일

### /etc/passwd

```text
user01:x:1000:1000:User One:/home/user01:/bin/bash
```

필드는 사용자명, 암호 표시자, UID, 기본 GID, 설명, 홈 디렉터리, 로그인 Shell 순서다. 실제 암호 해시는 `/etc/shadow`에 저장된다.

### /etc/group

```text
dev:x:2000:user01,user02
```

필드는 그룹명, 암호 표시자, GID, 보조 그룹 구성원 순서다.

### /etc/shadow

일반 사용자가 읽을 수 없도록 보호되며 암호 해시와 변경일, 최소·최대 사용 기간, 경고일, 비활성 기간, 만료일을 저장한다.

## 3. su와 sudo

```bash
su user01
su - user01
sudo systemctl restart sshd
```

- `su user01`: 사용자만 변경하고 현재 환경을 상당 부분 유지한다.
- `su - user01`: 대상 사용자의 로그인 Shell 환경을 새로 적용한다.
- `sudo`: 허용된 명령만 다른 사용자 권한으로 실행한다. 누가 어떤 명령을 실행했는지 기록하기 쉬워 운영 환경에 더 적합하다.

`sudo` 정책은 `visudo`로 편집한다. 문법 오류를 검사하기 때문에 `/etc/sudoers`를 일반 편집기로 직접 수정하는 것보다 안전하다.

```bash
visudo
```

예시는 다음과 같다.

```text
%wheel ALL=(ALL) ALL
%webadmin ALL=(root) /usr/bin/systemctl restart httpd
```

첫 줄은 `wheel` 그룹에 일반적인 관리자 권한을 부여한다. 두 번째 줄은 `webadmin` 그룹에 `httpd` 재시작 명령만 허용한다. 가능하면 전체 권한 대신 필요한 명령만 위임한다.

## 4. 사용자 계정 관리

```bash
useradd user01
passwd user01
usermod -c "User One" user01
usermod -s /bin/bash user01
usermod -L user01
usermod -U user01
userdel -r user01
```

- `useradd`: 사용자를 생성한다.
- `passwd`: 암호를 설정하거나 변경한다.
- `usermod`: 설명, Shell, 그룹, 잠금 상태 등을 변경한다.
- `userdel -r`: 계정과 홈 디렉터리를 함께 삭제한다. 필요한 데이터가 없는지 먼저 확인한다.

계정 잠금은 암호 로그인을 막는 조치다. 이미 실행 중인 세션이나 SSH 공개키 등 다른 인증 방식까지 모두 차단하는 조치와는 구분해야 한다.

## 5. 그룹 관리

```bash
groupadd dev
groupmod -n developers dev
groupdel developers
usermod -g developers user01
usermod -aG wheel,developers user01
gpasswd -d user01 developers
```

`usermod -g`는 기본 그룹을 변경한다. 보조 그룹을 추가할 때는 `-aG`를 사용한다. `-G`만 사용하면 기존 보조 그룹 목록이 지정한 목록으로 교체될 수 있으므로 주의한다.

새 그룹 권한은 기존 로그인 세션에 즉시 반영되지 않을 수 있다. 다시 로그인하거나 필요할 때 `newgrp 그룹명`으로 새 Shell에서 적용한다.

## 6. 암호와 계정 만료 정책

```bash
chage -l user01
chage -m 1 -M 90 -W 7 user01
chage -E 2026-12-31 user01
passwd -e user01
```

- `-m`: 암호를 다시 바꾸기 전 최소 사용 일수
- `-M`: 암호 최대 사용 일수
- `-W`: 만료 전 경고 일수
- `-E`: 계정 만료일
- `passwd -e`: 다음 로그인 시 암호 변경을 요구한다.

`/etc/login.defs`에는 계정 생성 시 사용할 기본 UID/GID 범위와 암호 만료 기본값 등이 있다. 그러나 암호 길이와 복잡성의 실제 인증 정책은 RHEL에서 PAM과 `pwquality` 설정도 함께 확인해야 한다.

## 7. 운영 시 확인할 점

계정을 추가하거나 권한을 변경한 뒤에는 설정 파일만 보지 말고 실제 결과를 확인한다.

```bash
id user01
sudo -l -U user01
getent passwd user01
getent group developers
```

운영 계정 관리는 최소 권한, 개인별 계정 사용, 불필요한 계정의 잠금·삭제, 변경 기록이라는 원칙을 함께 지켜야 한다.
