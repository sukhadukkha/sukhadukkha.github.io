Linux 관리 작업은 명령의 결과를 필요한 형태로 가공하고 반복 작업을 자동화하는 경우가 많다. 표준 입출력, 파이프, Vim, 변수, Bash 스크립트와 정규표현식을 정리한다.

## 1. 표준 입출력

프로세스는 기본적으로 세 개의 파일 디스크립터를 사용한다.

| 번호 | 이름 | 기본 대상 |
|---:|---|---|
| 0 | 표준 입력(stdin) | 키보드 |
| 1 | 표준 출력(stdout) | 터미널 |
| 2 | 표준 오류(stderr) | 터미널 |

리다이렉션은 이 입력과 출력의 목적지를 바꾼다.

```bash
command > output.txt
command >> output.txt
command 2> error.txt
command > output.txt 2>&1
command < input.txt
```

- `>`: 파일을 새로 만들거나 기존 내용을 덮어쓴다.
- `>>`: 기존 파일 끝에 추가한다.
- `2>`: 오류 출력만 저장한다.
- `2>&1`: 표준 오류를 현재 표준 출력과 같은 곳으로 보낸다.

## 2. 파이프와 tee

파이프(`|`)는 왼쪽 명령의 표준 출력을 오른쪽 명령의 표준 입력으로 전달한다.

```bash
ps aux | grep sshd
journalctl -u sshd | tail -20
```

`tee`는 입력받은 내용을 화면과 파일에 동시에 보낸다.

```bash
ip addr | tee network-info.txt
date | tee -a operation.log
```

`tee -a`는 파일을 덮어쓰지 않고 끝에 추가한다. root 권한이 필요한 파일에 결과를 저장할 때도 유용하다.

```bash
echo "192.168.1.10 server1" | sudo tee -a /etc/hosts
```

## 3. Vim 기본 사용

Vim은 명령 모드와 입력 모드를 구분한다.

| 작업 | 키 또는 명령 |
|---|---|
| 입력 모드 진입 | `i`, `a`, `o` |
| 명령 모드 복귀 | `Esc` |
| 저장 | `:w` |
| 종료 | `:q` |
| 저장 후 종료 | `:wq` |
| 강제 종료 | `:q!` |
| 검색 | `/문자열` |
| 다음 검색 결과 | `n` |
| 현재 줄 삭제 | `dd` |
| 붙여넣기 | `p` |
| 실행 취소 | `u` |

설정 파일을 수정하기 전에는 백업하고, 수정 후 서비스가 제공하는 문법 검사 명령이 있다면 먼저 실행한다.

## 4. Shell 변수와 환경 변수

```bash
name="server01"
echo "$name"
export APP_ENV=production
env | grep APP_ENV
unset APP_ENV
```

Shell 변수는 현재 Shell에서 사용한다. `export`한 환경 변수는 이후 실행되는 자식 프로세스에도 전달된다. 변수 대입 시 `=` 양옆에는 공백을 넣지 않는다.

명령 결과도 변수에 저장할 수 있다.

```bash
today=$(date +%F)
kernel=$(uname -r)
```

문자열 안에서 변수 경계를 분명하게 하려면 `${변수명}`을 사용한다.

## 5. Bash 스크립트 기본 구조

```bash
#!/bin/bash

set -u

target="/var/log/messages"

if [[ -f "$target" ]]; then
    echo "파일이 존재합니다: $target"
else
    echo "파일을 찾을 수 없습니다: $target" >&2
    exit 1
fi
```

첫 줄의 shebang은 스크립트를 실행할 인터프리터를 지정한다. 실행 권한을 부여한 뒤 실행한다.

```bash
chmod +x check-log.sh
./check-log.sh
```

### 조건문과 반복문

```bash
for service in sshd chronyd firewalld; do
    if systemctl is-active --quiet "$service"; then
        echo "$service: active"
    else
        echo "$service: inactive"
    fi
done
```

변수를 큰따옴표로 감싸면 공백이나 특수문자가 포함된 값이 의도치 않게 여러 인수로 나뉘는 것을 막을 수 있다.

### 종료 상태

Linux 명령은 성공하면 일반적으로 0, 실패하면 0이 아닌 종료 상태를 반환한다.

```bash
systemctl is-active --quiet sshd
echo $?
```

스크립트에서는 출력 문자열만 비교하기보다 종료 상태를 이용하면 더 안정적으로 판단할 수 있다.

## 6. grep과 정규표현식

`grep`은 텍스트에서 패턴과 일치하는 줄을 찾는다.

```bash
grep root /etc/passwd
grep -i error app.log
grep -n '^Sep' /var/log/messages
grep -E 'error|fail|denied' app.log
grep -v '^#' config.conf
```

- `-i`: 대소문자를 구분하지 않는다.
- `-n`: 줄 번호를 표시한다.
- `-E`: 확장 정규표현식을 사용한다.
- `-v`: 일치하지 않는 줄을 출력한다.

자주 쓰는 정규표현식은 다음과 같다.

| 표현 | 의미 |
|---|---|
| `^text` | `text`로 시작 |
| `text$` | `text`로 끝남 |
| `.` | 임의의 문자 1개 |
| `*` | 앞 요소가 0회 이상 |
| `[0-9]` | 숫자 1개 |
| `[^#]` | `#`이 아닌 문자 1개 |

## 7. 파일 보관과 전송

```bash
tar -czf etc-backup.tar.gz /etc
tar -tzf etc-backup.tar.gz
tar -xzf etc-backup.tar.gz -C /restore
scp report.txt user@server:/tmp/
rsync -av /data/ user@server:/backup/data/
```

`tar`는 여러 파일을 하나로 묶고, `-z`는 gzip 압축을 적용한다. 복원 전에는 `-t`로 내용을 확인하는 습관이 안전하다. `rsync`는 변경된 부분 중심으로 동기화할 수 있어 반복 전송에 적합하다.

쉘 스크립트는 작은 자동화에 유용하지만, 운영 환경에서는 입력값 검증, 오류 처리, 로그, 실행 권한과 재실행 시 결과까지 함께 고려해야 한다.
