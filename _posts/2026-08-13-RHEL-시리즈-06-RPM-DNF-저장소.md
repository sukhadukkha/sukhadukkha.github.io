RHEL의 소프트웨어는 주로 RPM 패키지로 제공되며 DNF가 패키지와 의존성, 저장소를 관리한다. 패키지 확인과 설치, 저장소 구성, ISO 기반 오프라인 저장소와 설치 자동화를 정리한다.

## 1. RPM 패키지

RPM 패키지에는 프로그램 파일뿐 아니라 이름, 버전, 아키텍처, 의존성, 설치 스크립트 같은 메타데이터가 포함된다.

```bash
rpm -q bash
rpm -qi bash
rpm -ql bash
rpm -qf /usr/bin/bash
rpm -qc openssh-server
rpm -V openssh-server
```

- `-q`: 설치 여부와 버전을 조회한다.
- `-i`: 패키지 상세 정보를 표시한다.
- `-l`: 패키지가 설치한 파일 목록을 표시한다.
- `-f`: 특정 파일을 제공한 패키지를 찾는다.
- `-c`: 설정 파일을 표시한다.
- `-V`: 설치 당시 메타데이터와 현재 파일을 비교한다.

`rpm`으로 패키지를 직접 설치할 수 있지만 필요한 의존 패키지를 자동으로 해결하지 못할 수 있다. 일반적인 설치와 업데이트는 DNF를 사용한다.

## 2. DNF 기본 명령

```bash
dnf search nginx
dnf info nginx
dnf provides '/usr/bin/semanage'
dnf install nginx
dnf remove nginx
dnf updateinfo
dnf check-update
dnf history
dnf repolist -v
```

DNF는 활성화된 저장소의 메타데이터를 읽고 필요한 의존 패키지를 함께 처리한다. `dnf provides`는 필요한 명령이나 파일이 어느 패키지에 포함되는지 찾을 때 유용하다.

운영 서버의 업데이트는 변경 범위와 서비스 영향, 재부팅 필요 여부, 복구 방법을 확인한 뒤 적용한다.

## 3. Repository

Repository는 RPM 패키지와 패키지 정보를 담은 메타데이터를 제공하는 저장소다. 설정 파일은 일반적으로 `/etc/yum.repos.d/*.repo`에 둔다.

```ini
[BaseOS]
name=BaseOS
baseurl=file:///mnt/repo/BaseOS
enabled=1
gpgcheck=0

[AppStream]
name=AppStream
baseurl=file:///mnt/repo/AppStream
enabled=1
gpgcheck=0
```

- `BaseOS`: 운영체제의 기본 기능에 필요한 핵심 패키지를 제공한다.
- `AppStream`: 런타임, 서버 애플리케이션 등 추가 소프트웨어를 제공한다.

실제 운영 환경에서는 가능한 경우 `gpgcheck=1`을 사용하고 신뢰할 수 있는 GPG 키로 패키지 서명을 검증한다.

## 4. RHEL ISO를 로컬 저장소로 사용하기

인터넷이나 Red Hat CDN을 사용할 수 없는 실습 환경에서는 DVD ISO를 마운트해 저장소로 사용할 수 있다.

```bash
mkdir -p /mnt/repo
mount /dev/sr0 /mnt/repo
ls /mnt/repo/BaseOS /mnt/repo/AppStream
dnf clean all
dnf repolist -v
```

재부팅 후에도 자동으로 마운트하려면 장치의 UUID나 적절한 장치 경로를 확인한 뒤 `/etc/fstab`에 등록한다. 가상머신에서 ISO 연결이 해제되면 저장소도 사용할 수 없으므로 ISO 연결 상태를 함께 확인한다.

`Unable to read consumer identity`는 시스템이 Red Hat Subscription에 등록되지 않았다는 뜻이다. 로컬 저장소가 올바르게 구성됐다면 패키지 사용 자체와는 별개의 메시지일 수 있다.

## 5. 패키지 그룹과 모듈

```bash
dnf group list
dnf group info "Development Tools"
dnf module list
```

패키지 그룹은 특정 목적에 필요한 여러 패키지를 묶어 제공한다. AppStream 모듈은 일부 소프트웨어의 여러 버전 흐름을 제공하지만 RHEL 버전에 따라 사용 방식과 제공 범위가 달라질 수 있으므로 현재 시스템 문서를 확인한다.

## 6. RHEL 설치 방식

RHEL은 ISO를 이용한 대화형 설치 외에도 Kickstart를 이용해 설치 과정을 자동화할 수 있다. Kickstart 파일에는 언어, 네트워크, 디스크 파티션, 사용자, 패키지와 설치 후 작업 등을 정의한다.

```text
설치 미디어 부팅
  → Kernel과 설치 환경 로드
  → 설치 소스 확인
  → 디스크·네트워크·계정 설정
  → 패키지 설치
  → 부트로더 구성
  → 재부팅
```

대량 배포에서는 표준 Kickstart와 PXE 부팅을 조합할 수 있다. 설치 자동화 파일에는 암호나 키 같은 민감 정보를 평문으로 남기지 않도록 관리해야 한다.

패키지를 설치한 뒤에는 명령 실행 여부만 확인하지 않고, 설치 버전과 설정 파일, 서비스 상태, 열린 포트와 로그까지 확인해야 실제 사용 준비가 끝난다.
