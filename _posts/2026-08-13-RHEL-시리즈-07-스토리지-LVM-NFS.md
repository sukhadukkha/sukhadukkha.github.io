서버가 디스크를 인식했다고 바로 파일을 저장할 수 있는 것은 아니다. 장치 확인, 파티션이나 LVM 구성, 파일시스템 생성, 마운트의 순서가 필요하다. 네트워크 스토리지인 NFS까지 함께 정리한다.

## 1. 블록 장치와 파일시스템 확인

```bash
lsblk -f
blkid
df -hT
findmnt
du -sh /var/* 2>/dev/null
```

- `lsblk -f`: 디스크, 파티션, LVM, 파일시스템과 마운트 지점을 트리로 보여준다.
- `blkid`: UUID와 파일시스템 유형을 확인한다.
- `df -hT`: 마운트된 파일시스템의 전체·사용·가용 공간을 확인한다.
- `findmnt`: 어떤 장치가 어느 경로에 어떤 옵션으로 마운트됐는지 보여준다.
- `du`: 디렉터리 내부 파일이 실제로 차지하는 공간을 합산한다.

`df`와 `du`는 측정 대상이 다르다. 삭제됐지만 프로세스가 계속 열고 있는 파일, 파일시스템 메타데이터, 예약 공간 때문에 값이 다를 수 있다.

## 2. 파티션과 파일시스템 생성

아래 과정은 대상 장치의 기존 데이터를 지울 수 있으므로 장치명을 반드시 확인한 뒤 실습 장비에서 수행한다.

```bash
parted /dev/sdb print
parted /dev/sdb mklabel gpt
parted /dev/sdb mkpart primary 1MiB 10GiB
partprobe /dev/sdb
mkfs.xfs /dev/sdb1
mkdir -p /data
mount /dev/sdb1 /data
```

마운트는 파일시스템을 Linux 디렉터리 트리의 특정 경로에 연결하는 작업이다. 마운트 지점에 기존 파일이 있으면 삭제되는 것은 아니지만 마운트 중에는 보이지 않으므로 빈 디렉터리를 사용하는 것이 안전하다.

## 3. 영구 마운트와 /etc/fstab

수동 `mount`는 재부팅하면 사라진다. 영구 마운트는 `/etc/fstab`에 등록한다.

```bash
blkid /dev/sdb1
```

```text
UUID=확인한-UUID  /data  xfs  defaults  0  0
```

수정 후 재부팅부터 하지 말고 다음과 같이 검사한다.

```bash
mount -a
findmnt --verify
findmnt /data
```

`fstab` 오류는 부팅 문제로 이어질 수 있다. 네트워크 파일시스템에는 `_netdev` 등 네트워크 준비를 고려한 옵션이 필요할 수 있다.

## 4. Swap

Swap은 메모리가 부족할 때 비활성 메모리 페이지를 저장하는 공간이며 최대 메모리를 단순히 늘리는 장치는 아니다. 지속적인 Swap 사용은 성능 저하의 신호일 수 있다.

```bash
free -h
swapon --show
mkswap /dev/sdb2
swapon /dev/sdb2
swapoff /dev/sdb2
```

영구 사용은 `/etc/fstab`에 `swap` 유형으로 등록한다.

## 5. LVM 구조

LVM은 물리 저장장치를 논리적으로 묶고 필요한 크기로 나누어 사용하는 계층이다.

```text
Disk 또는 Partition
        ↓
PV(Physical Volume)
        ↓
VG(Volume Group)
        ↓
LV(Logical Volume)
        ↓
Filesystem → Mount Point
```

### LVM 생성

```bash
pvcreate /dev/sdb
vgcreate vg_data /dev/sdb
lvcreate -L 20G -n lv_app vg_data
mkfs.xfs /dev/vg_data/lv_app
mkdir -p /srv/app
mount /dev/vg_data/lv_app /srv/app
```

```bash
pvs
vgs
lvs
```

### LVM과 파일시스템 확장

```bash
lvextend -L +10G -r /dev/vg_data/lv_app
```

`-r`은 LV 확장 후 파일시스템도 함께 확장한다. 분리해서 수행할 경우 XFS는 `xfs_growfs 마운트지점`, ext4는 `resize2fs 장치`를 사용한다. XFS는 일반적으로 온라인 확장은 가능하지만 축소는 지원하지 않는다.

## 6. Stratis

Stratis는 RHEL에서 여러 블록 장치를 pool로 묶고 filesystem을 제공하는 스토리지 관리 계층이다. 내부적으로 XFS와 장치 관리 기술을 사용하며 thin provisioning과 snapshot 같은 기능을 제공한다.

```bash
stratis pool create pool1 /dev/sdc
stratis filesystem create pool1 fs1
stratis pool list
stratis filesystem list
```

Stratis 파일시스템은 부팅 시 필요한 서비스와 마운트 옵션을 함께 고려해야 한다. 환경에서 표준으로 사용하는 LVM이나 스토리지 솔루션이 있다면 운영 정책을 우선한다.

## 7. NFS

NFS는 서버가 내보낸 디렉터리를 다른 Linux 시스템이 네트워크를 통해 마운트해 로컬 디렉터리처럼 사용하는 방식이다.

```bash
showmount -e 192.168.1.233
mkdir -p /srv/story/media
mount -t nfs 192.168.1.233:/pjh-nfs-test /srv/story/media
findmnt -T /srv/story/media
```

마운트 확인 후 읽기·쓰기를 실제로 검증한다.

```bash
touch /srv/story/media/.write-test
ls -l /srv/story/media/.write-test
rm /srv/story/media/.write-test
```

마운트는 성공했지만 쓰기가 거부된다면 서버의 export 접근 범위, 읽기·쓰기 설정, root squash, 파일 UID/GID와 디렉터리 권한을 함께 확인한다.

## 8. Autofs

Autofs는 경로에 접근할 때 NFS를 자동 마운트하고 일정 시간 사용하지 않으면 해제한다. 다수의 공유를 항상 마운트해 둘 필요가 없을 때 유용하다.

```text
/etc/auto.master.d/nfs.autofs
/-  /etc/auto.nfs
```

```text
/srv/share  -rw  server:/export/share
```

```bash
systemctl enable --now autofs
ls /srv/share
```

스토리지 구성은 장치 인식, 파일시스템, 마운트, 권한이 모두 연결돼야 완성된다. 변경 전 장치와 데이터를 확인하고, 변경 후 `lsblk`, `findmnt`, 실제 읽기·쓰기로 결과를 검증한다.
